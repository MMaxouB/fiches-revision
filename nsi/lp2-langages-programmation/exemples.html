    def carree(a: float) -> float:

help(carree)
  3. help(carree) affiche, dans la console, le prototype et le docstring de la fonction

LP2Variables locales et globales

Dans une fonction, une variable qui n'est ni un paramètre ni déclarée global n'a pas de valeur avant d'être affectée.

Trois fonctions carréOn écrit les trois fonctions suivantes. Que se passe-t-il pour carre(3), carre_2() et carre_3() ?
  1. Programme Python
    def carre(x):
    x = x**2
    return x

def carre_2():
    x = x**2
    return x

def carre_3():
    global x
    x = x**2
    return x
  2. carre(3) : x est le paramètre, donc local. Le calcul se fait et la fonction renvoie 9
  3. carre_2() : la ligne x = x**2 doit lire x avant de lui donner une valeur, mais x est local et n'a pas de valeur : Python lève UnboundLocalError †
  4. carre_3() : global x désigne la variable globale x. Si elle n'existe pas, NameError ; si on a écrit x = 3 avant, la fonction renvoie 9 et change la variable globale
Conclusion
à privilégier : carre (variable locale), pas de variable globale

Le cours demande d'essayer les trois fonctions et dit seulement qu'il y en a une qui ne peut pas être interprétée : le détail des messages d'erreur est un ajout.

LP2Préconditions avec assert

Une précondition se vérifie au début de la fonction, avant tout calcul.

Une fonction fragileVoici get_unite. Que renvoient get_unite(4567), get_unite(45.67) et get_unite(-6) ?
  1. Programme Python
    def get_unite(n: int) -> int:
    """
    renvoie le chiffre des unités d'un entier n
    """
    while n >= 10:      # répétition tant que n est supérieur ou égal à 10
        n = n - 10
    return n
  2. get_unite(4567) : on retire 10 tant que n >= 10 ; il reste 7
  3. get_unite(45.67) : même boucle avec des flottants, il reste 5.670000000000002 (arrondi de la machine) : ce n'est pas un chiffre des unités
  4. get_unite(-6) : -6 >= 10 est faux, la boucle ne s'exécute pas : la fonction renvoie -6
Conclusion
75.670000000000002−6 : deux résultats ne conviennent pas
Ajouter les préconditionsAjouter à get_unite les deux préconditions : n est un entier, n est positif ou nul. Que donnent alors get_unite(45.67) et get_unite(-6) ?
  1. Programme Python
    def get_unite(n: int) -> int:
    """
    renvoie le chiffre des unités d'un entier n
    """
    # "Précondition 1"
    assert type(n) == int, "vous devez entrer un nombre entier."
    # "Précondition 2"
    assert n >= 0, "le nombre étudié doit être positif ou nul."

    while n >= 10:
        n = n - 10
    return n
  2. get_unite(45.67) : type(n) == int est faux, l'exécution s'arrête avec AssertionError: vous devez entrer un nombre entier. †
  3. get_unite(-6) : le type est bon, mais n >= 0 est faux : AssertionError: le nombre étudié doit être positif ou nul. †
  4. get_unite(4567) : les deux conditions sont vraies, les assertions ne font rien et la fonction renvoie 7
Conclusion
l'appel incorrect s'arrête avec un message clair

Ordre à respecter : on teste d'abord le type, puis le signe (comparer une chaîne à un entier provoquerait une erreur de type).

LP2Postconditions avec assert

Une postcondition se vérifie juste avant le return, sur la valeur qu'on va renvoyer.

Les trois postconditionsÉcrire les postconditions de get_unite : le résultat est un entier, positif ou nul, strictement inférieur à 10.
  1. Juste avant return n, une assertion par contrainte, avec un message clair
  2. Programme Python
    def get_unite(n: int) -> int:
    """
    renvoie le chiffre des unités d'un entier n
    """
    while n >= 10:
        n = n - 10
    # "Postcondition 1"
    assert type(n) == int, "Le nombre renvoyé devrait être un entier."
    # "Postcondition 2"
    assert n >= 0, "le nombre renvoyé doit être positif ou nul."
    # "Postcondition 3"
    assert n < 10, "le nombre renvoyé doit être inférieur à 10."
    return n
  3. Si la fonction est correcte, les trois assertions sont vraies et ne font rien
Conclusion
assert avant le return
Une postcondition qui échoue †On a écrit par erreur n = n - 9 dans la boucle. Que se passe-t-il pour get_unite(10) ?
  1. Programme Python
    def get_unite(n: int) -> int:
    """renvoie le chiffre des unités d'un entier n"""
    assert type(n) == int and n >= 0
    while n >= 10:
        n = n - 9          # faute : on retire 9 au lieu de 10
    assert 0 <= n < 10, "le nombre renvoyé doit être compris entre 0 et 9."
    return n
  2. n = 10 : la boucle retire 9, donc n vaut 1. La condition n >= 10 est fausse, la boucle s'arrête
  3. 0 <= 1 < 10 est vrai : l'assertion ne se déclenche pas, mais le résultat est faux (le chiffre des unités de 10 est 0)
  4. Pour get_unite(25) : 25 devient 16 puis 7 : la fonction renvoie 7 au lieu de 5
Conclusion
une postcondition ne remplace pas les tests : ici elle n'a rien vu

Cet exemple est un ajout : les postconditions vérifient la forme du résultat, pas sa valeur exacte. C'est pourquoi on écrit aussi un jeu de tests.

LP2Jeux de tests

Un jeu de tests est une suite d'assertions : si tout est vrai, rien ne s'affiche.

Tester ajoute_1Écrire un jeu de tests pour ajoute_1. Que se passe-t-il avec le test faux assert ajoute_1(2) == -2 ?
  1. Programme Python
    def ajoute_1(x):
    return x + 1

# Jeu de tests
assert ajoute_1(2) == 3
assert ajoute_1(-2) == -1
  2. Les deux assertions sont vraies : l'exécution ne renvoie rien
  3. Avec assert ajoute_1(2) == -2, la condition est fausse (3 != -2)
  4. Programme Python
    assert ajoute_1(2) == -2
AssertionError
Conclusion
test vrai : rien ; test faux : AssertionError
Choisir les cas †Proposer un jeu de tests pour get_unite (la version avec la boucle n - 10).
  1. Un cas courant (4567), le plus petit cas (0), le plus grand chiffre (9) et une valeur où le chiffre repasse à 0 (10)
  2. Programme Python
    # Jeu de tests pour get_unite (cas courants et cas limites)
assert get_unite(0) == 0
assert get_unite(9) == 9
assert get_unite(10) == 0
assert get_unite(4567) == 7
  3. Ces quatre assertions sont vraies pour la version correcte (n - 10) ; elles échouent pour la version fautive (n - 9) : get_unite(10) y renvoie 1
Conclusion
suffisamment de cas pour avoir confiance dans la fonction
